Canvas admin bookmarklets

Small browser tools that run inside a Canvas tab you are already signed in to. No tokens, no third parties, no remote code.

Cross-list sections

Cross-list sections

Drag this to your bookmarks bar. Clicking it here will not do anything useful.

Version 2.1.0
Runs on any page of your Canvas instance
Needs a role that can cross-list sections
Last tested 18 September 2026, Chrome and Firefox

Moves sections out of one or more secondary courses and into a primary course, in one pass. Find the primary course, add up to nine secondary courses, check the sections you want, and read the summary before you commit to anything.

Sections start unchecked, so every move is deliberate. The panel tells you how many sections and how many student enrollments are about to move, and where they will land. Click the bookmark once to open the panel and again to close it.

Cross-list before the term opens. Moving a section out of a course that has already started leaves its submissions and grades behind in the source course, where those students can no longer reach them. Un-cross-listing returns the section but does not reconcile work done in the primary course in the meantime. Check for submitted work before you move anything in a live course.

Cross-listing moves student enrollments, so those students do their coursework in the primary course from that point forward. Source courses keep their own content, settings, and any sections you left unchecked.

Sections already cross-listed somewhere else appear in red. Moving one of those relocates it a second time rather than returning it home.

Undo and the audit record

After a run, an undo button returns those sections to their home courses. That button only exists in the browser tab you ran it in. Close or reload the tab and it is gone.

Every completed run also prints a copyable audit record: a timestamp, the destination course, and one line per section naming its ID, SIS ID, and the home course it came from. That record is both your change-management artifact and your manual recovery path, since returning a section by hand means opening the primary course, going to Settings > Sections, and de-cross-listing it back to the course named in the record. Paste it into your ticket before you close the tab.

Add or remove one enrollment

Add or remove enrollment

Drag this to your bookmarks bar. Read the caution below first.

Version 1.1.0
Runs on any page of your Canvas instance
Needs the Import SIS Data permission on your admin role
Last tested 18 September 2026, Chrome and Firefox

Puts one person on one section in one role, or takes them off it. Search for the user, search for the course, pick the section, choose the role and whether you are adding or removing, and read the two-line CSV the panel shows you before you send it.

This exists because the enrollments API refuses to touch a concluded course. Every fall, someone needs a designer added to last spring's section to copy content out of it, and the supported answer is to unconclude the course, add the person, and remember to conclude it again. This writes a two-row SIS import instead, which reaches concluded and past-term courses without changing the course state.

This is the sharpest tool here. Know what it does before you run it.

The enrollment it creates becomes SIS-managed. Instructors cannot remove an SIS-managed enrollment from their own course, and a future SIS import running in batch mode can delete it as an orphan, because your nightly feed does not know it exists. Check how your institution runs its enrollment imports before you use this on a course that the SIS still feeds.

The tool never sends batch_mode and never sends diffing_data_set_identifier, which is what keeps a two-row CSV from ever sweeping a term. Both omissions are deliberate. Leave them that way if you fork it.

SIS imports run at the account level. If you open the panel from a page that does not name an account, it searches from your root account and says so in an amber line. Open the account you actually mean and click the bookmarklet from there.

After the import finishes, the panel polls for the result, re-reads the section roster to confirm the enrollment actually landed, and prints a one-line audit record with the import ID, the SIS IDs, the role, and the timestamp. Copy that into your ticket. A SIS import that reports success while the roster disagrees is exactly the case the verification step is there to catch.

Why you can run this

Running a stranger's JavaScript inside an authenticated admin session deserves suspicion. Here is what this does, so you can check rather than trust.

  • No tokens. Authentication is the session cookie and _csrf_token cookie Canvas already set in your browser.
  • No third parties. Every request goes to the Canvas origin in your address bar, read at runtime from location.origin. Nothing leaves it.
  • No remote code. No eval, no injected <script>, no injected <style>. The panel is built with DOM calls, which is also why it works under Content Security Policy.
  • Your permissions still apply. It calls the same API your account already has. If your role cannot cross-list, neither can this.

The readable sources live in src/. The encoded builds in dist/ are the same code with comments stripped.

Installing without dragging

Show your bookmarks bar with Ctrl/Cmd+Shift+B, right-click it, choose Add page in Chrome or Add Bookmark in Firefox, name it, and paste the contents of the matching file in dist/ into the URL field.

When it breaks

Instructure ships to production every few weeks. This calls the REST API rather than scraping the page, which makes it more durable than most bookmarklets, but API behavior still changes. If it stops working, open an issue with your browser and whatever the panel said when it failed.

I maintain this as time allows, and I read every issue. Treat it as a tool one admin wrote and shared rather than a supported product, and test it against your own instance before you rely on it during a term.
